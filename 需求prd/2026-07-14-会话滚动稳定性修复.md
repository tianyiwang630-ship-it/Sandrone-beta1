# 2026-07-14 会话滚动稳定性修复

## 背景/原因

Web 对话区原先只用一个全局 `scrollTop` 临时保存位置，没有区分 session，也没有持久化。切换到较短会话、页面长期处于后台、电脑休眠或前端容器重新加载后，原会话的阅读位置会丢失并回到顶部。

流式回答结束时，正式历史消息会先加入页面，流式消息随后才被移除，导致两份回答短暂同时存在。消息区同时启用了全局平滑滚动，因此内容高度先增后减时会出现明显的上下晃动。

## 具体设计

### 滚动行为

- 每个 session 独立记录阅读位置，并写入浏览器本地存储；页面或未来 EXE 前端容器重新加载后仍可恢复。
- 切换 session 前保存当前会话位置，新会话详情完成渲染后再恢复它自己的位置，不允许跨 session 共用位置。
- 新消息和流式增量出现时始终保持用户原来的阅读位置，即使用户原本位于底部，也不主动拉到最新内容。
- 如果历史内容缩短，保存位置超过当前最大可滚动范围，只截断到当前可用范围。
- 本地存储不可用、记录损坏、数值非法时按顶部位置安全降级，不影响聊天功能。

### 刷新与流式交接

- session 详情请求发出前立即采集滚动位置，并用逐 session 请求序号阻止过期响应覆盖新结果。
- `focus` 和 `visibilitychange` 触发的恢复刷新合并到同一帧；同一 session 的运行恢复任务只允许一份轮询。
- 流式任务完成后，先获得正式 session 快照，再在同一次 React 状态提交中加入正式消息、移除流式状态，避免重复消息造成高度反向变化。
- 用户待发送消息转为正式历史消息时采用同样的原子交接。
- 消息容器使用即时滚动，不再全局启用平滑滚动。

### 分层与兼容性

- 变更位于入口层 / Channel Layer 的消息渲染和滚动状态管理。
- 不修改 Gateway、FastAPI REST 接口、Agent Runtime 或 session 持久化结构。
- 使用标准 DOM 和 localStorage，兼容当前 Web 入口与未来 WebView/EXE 前端容器。

## 验收标准

- 流式回答结束时，对话区不再因正式消息与流式消息重复而上下晃动。
- 在长、短 session 间往返后，各自恢复自己的阅读位置。
- 页面后台恢复、电脑休眠恢复和前端重新加载后，不会无故回到顶部。
- 新消息和流式内容不会打断用户当前阅读位置。
