# 子 agent 结果交付与停止边界修复

日期：2026-09-21

## 背景／原因

一次双子 agent 协作在实际工作完成后持续运行。原因是运行时把每轮结束结果同时发送给主 agent 和本轮来信者；A 的结束通知唤醒 B，B 的结束通知又唤醒 A，形成无需模型主动发消息也会继续的自动循环。

同一会话随后出现 Windows `WinError 5`。会话快照使用固定 `.json.tmp` 文件并直接替换正式文件；高频保存时，临时文件竞争或短暂文件占用会使替换失败。该错误不是循环的起点，但会使运行和会话状态进一步不稳定。

## 具体设计

### 消息与会话编排层

- 子 agent 每轮结束时，只向所属主 agent 交付一次结果，不自动通知曾向它发消息的其他子 agent。
- 子 agent 之间继续允许主动交流。需要答复同伴时，由 agent 明确调用消息工具。
- 结束结果使用 `subagent_result` 身份进入主 agent 邮箱，记录结果子 agent ID、执行 ID，以及本轮实际处理的委托消息 ID。创建或追加任务时工具立即返回的消息 ID，可与稍后到达的结果对应。
- 异步结果可以唤醒主 agent，但它不是普通协作来信，不会产生面向同伴的自动回执。

### 停止状态

- 主 agent 停止子 agent 后，子 agent 进入持久的 `stopped` 状态，保留 ID、上下文和历史。
- 只有所属主 agent 的新消息可以解除 `stopped` 并启动新一轮。
- 其他子 agent 向已经停止的目标发消息时，消息工具直接返回明确错误，不写入邮箱。
- 停止收尾过程中已经到达的同伴消息允许被记录，但收尾完成后标记为中断，不得自动启动目标。主 agent 在收尾期间发来的新任务可在旧执行完全退出后继续。
- 正常完成后的 `idle` 不受该限制，仍可由同伴主动消息唤醒。

### Workspace / Memory / State 持久化层

- `SessionStore` 在进程内串行执行快照替换。
- 每次保存使用独立临时文件，避免并发保存共用固定 `.tmp` 文件。
- Windows 短暂拒绝访问时进行有限退避重试，总等待时间有界；持续失败则向上抛错。
- 替换持续失败时删除本次临时文件并保留此前有效快照，不留下半写正式 JSON。

### CLI 入口层

- Windows PowerShell 启动脚本通过标准输出接收运行环境 JSON。该 JSON 使用 ASCII 转义传输，避免项目路径包含中文时被 PowerShell 按本地代码页误解码，随后把错误路径写回 `AGENT_ALPHA_ROOT`。

## 验收边界

- A、B 各自完成后，结果只进入主 agent；A、B 不因结束通知互相唤醒。
- 主 agent 能从结果记录核对来源 agent、执行和委托消息。
- 已停止子 agent 不能被同伴唤醒，主 agent 可以沿用原 ID 重新派活。
- 停止收尾期间的同伴消息不会在停止完成后启动新执行。
- 临时 `WinError 5` 可重试成功；持续失败保留旧快照并清理临时文件。
- 从包含中文的项目路径执行 `start-agent-alpha.ps1` 可以进入 CLI，并能正常退出。
- 使用后端测试验证，不使用浏览器测试。
