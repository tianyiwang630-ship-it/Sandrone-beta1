# 输出超限恢复与 Token 预算

## 背景/原因

一次包含工具调用的模型回复达到输出长度上限后，工具参数 JSON 被截断。后端先按工具参数解析失败处理，界面因此显示 `invalid tool call`，没有准确告诉模型“输出过长”，自动恢复也只收到了通用的结构纠错提示。

同时，项目中的默认输入窗口、压缩阈值和输出上限低于当前 DeepSeek 模型的使用预算，而且 Web 运行时默认值与内置 DeepSeek Profile 的值不一致。

本次迭代只处理输出超限恢复和默认 Token 预算，不增加强制分批机制，不调整新消息排队或前端交互。

## 具体设计

### 1. 输出超限识别

- 当供应商返回 `finish_reason="length"` 时，优先判定为输出被截断。
- 该判断先于工具参数解析，避免残缺 JSON 被误报为普通 `invalid tool call`。
- 纯文本回复即使没有工具调用，只要因长度结束，也视为未完成。
- 被截断的正文和工具调用不写入会话历史，不执行任何工具。

### 2. 两次提示恢复

- 第一次恢复提示模型缩短输出、拆小任务，本轮只完成下一小段；工具调用必须完整且简短。
- 第一次仍失败时，第二次提示更严格：不重复长内容、不长篇解释，只完成一个最小步骤或一个简短工具调用后停止。
- 提示只约束模型自行拆分，不由后端建立强制分批状态机。

### 3. 恢复耗尽后的会话行为

- 两次恢复仍失败时，停止当前轮并明确显示输出长度超限。
- 当前轮标记为可恢复失败；保留原有有效历史和本轮用户消息，不保存残缺 assistant 消息。
- 会话保持可用，用户发送下一条消息后可以继续对话。

### 4. 默认 Token 预算

- 默认输入上下文上限调整为 `600_000` tokens。
- 自动压缩阈值调整为可用历史空间的 `80%`。
- 默认最大输出调整为 `300_000` tokens。
- 内置 DeepSeek Flash/Pro Profile 同步为 `300_000`；其他供应商继续保留各自原有值。

## 所属 Harness 层

- Context / Prompt 组装层：调整输入上限和自动压缩阈值。
- Agent Loop 执行层：识别输出截断、注入两级恢复提示、恢复耗尽后结束当前轮。
- 模型接入配置：统一默认输出上限和 DeepSeek Profile 上限。

## 验收标准

- `finish_reason="length"` 不再显示为普通工具调用格式错误。
- 纯文本截断和工具调用截断均进入两次专用恢复。
- 两次恢复提示强度逐级增加，且总恢复次数固定为两次。
- 恢复耗尽后当前轮停止，会话仍可接收下一条消息。
- 残缺回复和工具调用不会进入历史，也不会触发工具执行。
- 默认输入、压缩阈值、默认输出分别为 600K、80%、300K。
