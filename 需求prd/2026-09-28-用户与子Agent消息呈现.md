# 2026-09-28：用户与子 Agent 消息呈现

## 背景与目的

聊天中的用户输入和子 Agent 协作消息仍会呈现为带绿色调的消息块，用户消息正文还沿用代码区的等宽字体，未完整采用 Codex 浅色聊天样式。子 Agent 返回的内容也被当作新的 `USER` 轮次显示，用户难以判断它是委托调用的结果还是新的用户指令。

本迭代要求让真实用户发言保持清楚可辨，同时把子 Agent 的通信结果归入对应的协作工具调用。子 Agent 消息不能制造新的用户轮次或侧边轮次定位点。

## 具体设计

### 用户消息样式

- 用户气泡采用白色、浅灰和深灰的中性色，不使用绿色背景或绿色边框。
- 正文使用聊天系统字体和既定默认字号：Windows 默认聊天正文字号 13px，正文行高为字号的 1.625 倍；等宽字体仅用于代码和命令内容。
- 保持用户消息右侧对齐、换行和长消息折行行为。

### 子 Agent 消息归属

- 真实用户消息继续按用户轮次显示。
- `source=agent`、`source=subagent_result` 或带有 Agent 来源标识的协作消息不再创建用户气泡或用户轮次。
- 子 Agent 消息作为协作调用结果显示在对应的 `subagent_create`、`subagent_message` 或 `agent_message` 工具卡片内。工具卡片继续保留调用参数和常规工具回执，并增加“子 Agent 消息”或“子 Agent 结果”内容区。
- 优先使用协作回执中的消息 ID 与结果消息的 `reply_to` 关联。异步结果在新的用户轮次之后抵达时，仍应回到原先的工具调用卡片，不能串入最新用户轮次。
- 无法匹配到特定工具调用时，将其保留在该会话的过程/工具输出区域，以协作消息卡片展示；不能降级成用户消息，也不能丢弃正文。
- 展示协作正文时去掉仅供 Agent 上下文使用的传输标记行，正文内容本身保持完整。内部关联 ID 仅用于匹配，不作为用户消息正文显示。
- 协作消息在实时事件和加载的历史记录中采用相同的归属规则；重复事件和历史副本只显示一次。

## 验收标准

- 用户消息背景和边框为中性色，正文采用系统聊天字体；不得被代码区等宽字体规则覆盖。
- 实际用户输入仍显示为 `USER` 气泡，并继续形成可导航的用户轮次。
- 子 Agent 的即时协作消息和异步完成结果不显示为 `USER` 气泡，不增加用户轮次或左侧轮次导航项。
- 子 Agent 消息按回执 ID 和 `reply_to` 显示在原始协作工具调用卡片内，即使它在另一条用户消息之后才到达。
- 没有精确工具调用关联时，消息仍显示在过程/工具输出区域，正文不丢失。
- 同一协作消息同时存在于运行事件与历史详情时只显示一次；纯用户消息不得误判为协作消息。
