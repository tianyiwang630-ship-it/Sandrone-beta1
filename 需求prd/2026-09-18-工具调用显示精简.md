# 2026-09-18 工具调用显示精简

## 背景/原因

Web 对话中同一类工具调用会经由实时事件和历史会话两条路径展示，部分界面直接带出了调用 ID、时间及内部事件信息。用户查看过程时真正需要的是：调用了哪个工具、传入了什么参数、工具输出了什么结果。现有参数和输出呈现也不统一，连续调用同名工具时不容易确认每个结果对应哪一次调用。

## 具体设计

- 变更位于入口层 / Channel Layer 的聊天展示层。实时事件和历史记录复用同一套工具调用呈现规则；不修改 FastAPI 接口、Gateway、消息与会话编排、会话持久化、Agent Runtime、Agent Loop 或实际工具执行逻辑。
- 每一次工具调用均渲染为独立的默认折叠块，标题只显示工具名称。内部调用 ID 继续仅用于将参数和结果准确配对，不作为界面内容展示；时间和内部事件类型也不展示。
- 展开工具块后只保留“参数”和“输出”两个区域。参数可解析时格式化为 JSON，解析失败时展示原文；输出保留换行，过长内容在区域内滚动查看。
- 同名工具连续调用、一次发起多个调用或结果乱序到达时，按调用 ID 归属到各自工具块。尚未返回结果时显示“执行中…”，聊天轮次结束后仍无结果时显示“未收到输出”，返回空内容时显示“无输出”，异常内容显示在输出区域。
- 助手在调用工具前生成的说明文字继续放在工具块外，完成后仍可见。结果到达时保持用户已展开的工具块状态，不因重新渲染自动折叠。
- 历史记录中无法匹配调用的结果单独以“工具输出”显示，保留原始内容，避免丢失旧会话信息。

## 验收标准

- 默认只能看到工具名称；展开后只能看到参数和输出，界面附加的调用 ID、时间和内部事件信息不显示。
- 实时执行和重新打开历史会话时，同一调用的参数和输出一致；同名连续调用、多调用和乱序结果不会串到其他工具块。
- 空参数、无法解析的参数、执行中、缺少结果、空输出、错误输出和长输出都有清晰且不丢内容的展示。
- 工具调用前的助手说明文字仍在工具块外可见；结果更新不会关闭已被用户展开的工具块。
- 前端相关测试、类型检查和生产构建通过，且不使用浏览器自动化测试。
