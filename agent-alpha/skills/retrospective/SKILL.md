# 复盘

这是显式调用 Skill。只处理消息中标记为 `[系统复盘任务]` 的复盘任务。

## 执行顺序

1. 调用 `load_skill` 加载 `planwithfile`，把 `task_plan.md`、`findings.md`、`progress.md` 创建在任务指定的过程文件目录。
2. 逐个读取任务列出的 event。event 是主要事实来源；每读取两批资料，把关键发现写入 `findings.md` 并更新进度。
3. 只有 event 无法解释关键问题、报错原因或工具执行细节时，才读取同一会话对应且任务列出的 log。log 是只读材料，不要写入、删除或修改 `session-log`。
4. 项目复盘时，若某个来源会话的第一条用户消息包含 `[系统复盘任务]`，跳过该会话。不要把 `复盘/` 中的旧报告当作来源。
5. 来源会话仍在运行时，只总结已经落盘的事实，并明确标注可能遗漏尚未完成的动作。
6. 只写任务指定的两份正式报告，不自行改变文件名。

## 增量 Log 的读取

`log_version: 3` 的 Log 只保存一次正文，用 `$log_ref` 引用；`llm_input.event.messages_delta` 记录历史变化，不能把它误认为完整模型输入。需要完整内容时，使用项目 Python 执行 `AGENT_ALPHA_ROOT/scripts/compact_realtime_logs.py <日志绝对路径> --read --event-type llm_input --limit 1`；可用 `--request-id` 定位一次执行。`--read` 只读取并展开记录，兼容旧日志；复盘时不要使用 `--replace` 或省略 `--read`。流式生成片段以 Event 为准，Log 保留完整回复和已捕获的失败片段。

## 工作复盘

给人看的报告必须包含：

- 复盘范围和截止时间。
- 背景、目标和原因。
- 用户作出的关键决策，以及 AI 执行的主要工作；两者分开描述。
- 关键选择及原因。
- 遇到的问题、尝试、结果和仍然存在的风险。
- 当前状态，明确区分已完成、未验证和未完成。
- 下一步建议。

不得把推测写成事实。重要结论尽量注明对应会话或事件依据。

## AI 交接报告

给 AI 看的报告必须包含：

- 项目目标和当前状态。
- 关键文件、路径和已确认决策。
- 失败过的方法、原因和不要重复踩的坑。
- 用户明确表达的要求。
- 推断出的偏好，必须标注“推断”及可信度，不得把单次行为写成稳定偏好。
- 未完成事项、风险和下一位 Agent 接手后的第一步。

## 完成回复

完成后在对话中简要讲述复盘结论，列出两份报告的准确路径，并明确提示：

> 如果需要让其他 AI 阅读，直接让它读取 AI交接报告即可；系统不会自动加载这份文件。
