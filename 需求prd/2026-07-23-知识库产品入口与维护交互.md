# 2026-07-23 知识库产品入口与维护交互

## 背景/原因

知识库 Skill 已通过“已有文档项目转换”和“空项目初始化”测试，并完成混合主题适配。下一步需要把显式提示词操作产品化，让用户通过按钮完成知识库初始化、增加资料、移除资料和全局整理，同时保留普通对话的透明度。

本次设计只确定产品入口、交互、提示词、知识库身份和异常边界，不实施代码。知识库仍由通用 Agent、正式 Skill 和本地 Markdown 文件完成，不增加数据库、向量检索、RAG 服务或独立 Agent 执行通道。

## 目标

1. 普通项目可以从项目列表显式改造为知识库。
2. 改造操作自动创建会话并发送可见的普通用户消息。
3. AI 先只读盘点并等待用户确认，不因点击按钮直接修改文件。
4. 转换真正完成后，产品才把项目识别为知识库。
5. 知识库项目在消息输入区提供增加、移除和全局整理入口。
6. 所有按钮复用现有会话、消息队列和 Agent Skill 链路。

## 非目标

- 不增加“新建知识库”项目类型或新建菜单项。
- 不提供一键撤销知识库转换。
- 不提供知识库结构异常提示。
- 不自动修复缺失的 Wiki 结构。
- 不隐藏按钮自动发送的消息。
- 不修改普通问答默认只读的规则。

## 一、项目改造入口

### 按钮位置

普通项目右侧操作按钮顺序调整为：

```text
固定 ｜ 改造为知识库（书本图标）｜ 重命名 ｜ 删除
```

书本按钮悬浮提示为“改造为知识库”。已经识别为知识库的项目不显示该按钮。

### 两次确认

点击书本按钮，在按钮附近显示第一层确认框：

```text
升级项目为知识库

否  是
```

- 点击“否”、点击外部或鼠标离开确认区域，关闭确认框。
- 点击“是”，第一层在原位置切换为第二层确认。

第二层文案：

```text
改造知识库会重新整理项目文件结构，但不会修改文档内容。
转换完成后不能一键撤销。

否  是
```

- 点击“否”关闭确认框。
- 点击第二次“是”后，临时禁用按钮，防止连续点击。

### 自动创建初始化会话

第二次确认后：

1. 为当前项目创建标题为“初始化知识库”的新会话。
2. 自动选择并进入新会话。
3. 以普通用户消息发送初始化提示词。
4. 消息正常进入会话历史、事件和日志，不使用隐藏系统提示词。
5. 发送请求结束后解除按钮临时禁用。

初始化提示词：

> 请使用 `managing-knowledge-wikis` Skill，将当前项目初始化为知识库。请先完整读取 Skill，自行判断当前项目属于“初始化空项目”还是“转换已有项目”。本轮先只读盘点项目文件，给出建议入库内容、暂不入库内容、资料关系和最小 Wiki 结构预览，不要修改或移动任何文件，等待我确认后再继续。

用户确认方案后，AI 按 Skill 执行。用户拒绝、停止回复或执行失败时，项目仍为普通项目。

## 二、知识库身份

### 项目标识

正式知识库使用项目内标识：

```text
.alpha/knowledge-base.json
```

最小内容：

```json
{
  "type": "knowledge-base",
  "version": 1,
  "created_at": "2026-07-23T12:00:00+08:00"
}
```

产品以标识文件是否存在判断项目身份，不在 alpha 项目状态中重复保存知识库布尔值。项目列表和项目详情接口返回派生字段 `is_knowledge_base`。

规则：

- 标识不存在：普通项目。
- 标识存在：知识库项目。
- `.alpha/` 存在但没有标识：普通项目。
- 不解析 Wiki 完整度，不显示结构异常提示。
- 外部知识库文件夹重新导入后可以直接识别。
- 标识只用于产品识别，不进入 Wiki 索引或知识问答。

### Skill 创建标识的时机

正式 Skill 必须增加“产品知识库标识”规则。初始化或转换未完成时不得创建标识。

只有完成以下检查后，才把创建标识作为最后一步：

1. 已确认资料处理完成。
2. `wiki/index.md` 和 `wiki/log.md` 已创建或更新。
3. 资料摘要和必要综合页已生成。
4. Markdown 相对链接验证完成。
5. `raw/` 原始资料未被改写。
6. 新知识库 `AGENTS.md` 已生成。

验证通过后：

- `.alpha/` 不存在时创建目录。
- 不覆盖 `.alpha/` 中的其他产品文件。
- 创建 `.alpha/knowledge-base.json`。
- 完成报告中说明标识已经创建。

执行失败、用户取消或仍在等待确认时，不得创建标识。AI 已经生成部分 Wiki 后失败，再次运行时先盘点现状并提出继续或修复方案，不盲目覆盖资料。

### 前端无感更新

后端每次返回项目列表或详情时，根据工作区标识计算 `is_knowledge_base`。

软件启动、加载项目、切换项目，以及每次 AI 运行结束后，前端获取最新项目状态。AI 运行结束后的状态检查只能更新当前项目对象：

- 不刷新页面。
- 不重新读取会话详情。
- 不改变当前项目或会话。
- 不改变输入框草稿。
- 不改变消息列表滚动位置。

现场转换完成并识别到标识后，项目行的改造按钮消失，当前消息框出现维护入口。

## 三、维护知识库入口

### 默认状态

只有 `is_knowledge_base=true` 的当前项目显示维护按钮。按钮位于消息输入框左下角、“对齐”按钮右侧：

```text
＋ ｜ 对齐 ｜ 书本图标
```

悬浮提示：

```text
维护知识库：增加、移除或全局整理
```

### 展开状态

点击书本图标后横向展开：

```text
增加 ｜ 移除 ｜ 全局整理                         −
```

- 点击减号收缩为书本图标。
- 执行增加、移除或全局整理后保持展开。
- 普通项目不显示该区域。

### 没有会话或正在运行

- 增加、全局整理：有当前会话时直接发送；没有会话时先自动新建；当前任务运行中时进入现有消息队列。
- 移除：只写入当前草稿；用户发送时沿用现有“无会话自动创建”机制。

## 四、增加资料

点击“增加”，自动发送可见的普通用户消息：

> 请使用 `managing-knowledge-wikis` Skill 的“新增资料”模式，检查当前项目中是否存在尚未加入知识库的新文档。请对照 `raw/`、`wiki/index.md`、`inbox/` 和项目中的其他文件，只做盘点，不要移动文件或修改 Wiki。列出发现的新资料、可能的重复资料、建议加入或暂不加入的内容，等待我确认后再执行。如果没有发现新文档，请提醒我先上传或下载资料。

该消息只授权盘点，不授权直接入库。用户确认后，AI 才按 Skill 移动资料、更新 Wiki、索引和日志。

## 五、移除资料

按钮名称使用“移除”，不使用“删”。悬浮说明：

```text
将资料移出活跃知识库并归档，原始文档不会被删除。
```

点击后只在输入框插入：

```text
我要从知识库移除以下资料：
```

- 输入框为空时直接插入，光标位于冒号后。
- 输入框已有内容时在当前光标位置插入；无法取得位置时追加到末尾。
- 不自动发送，不覆盖已有草稿。
- 用户没有填写资料名称就发送时，AI询问需要移除的资料。
- 用户填写后，AI先分析逻辑资料组、依赖页面和影响范围，等待确认后执行可恢复归档。

## 六、全局整理

点击“全局整理”，自动发送可见的普通用户消息：

> 请使用 `managing-knowledge-wikis` Skill 的“全库整理”模式，检查并维护当前知识库。请检查失效链接、重复或孤立页面、分类是否过细、暂未归类资料、缺失关联、来源可信度、相互矛盾的内容，以及归档资料是否仍残留在活跃 Wiki 中。低风险问题可以直接修复；涉及一级分类变化、大量页面移动或多个综合页拆分合并时，先给出调整预览并等待我确认。不要修改 `raw/` 中的原始文档，完成后更新索引和日志。

普通问答、单份资料新增和项目切换不自动触发全库整理。

## 七、实现分层

### 入口层 / Channel Layer

- 项目行增加改造按钮和两层确认框。
- 消息输入区增加知识库维护面板。
- 三段自动提示词集中存放，不散落在组件中。

### Gateway 控制平面层

- 项目接口增加派生字段 `is_knowledge_base`。
- 读取工作区内固定标识，不增加独立知识库状态表。

### 消息与会话编排层

- 初始化复用现有新建会话和发送消息接口。
- 增加和全局整理复用现有发送及排队机制。
- 所有自动消息都作为普通用户消息保存。

### Context / Prompt 组装层

- 不增加隐藏系统提示词。
- 正式 Skill 继续负责生成知识库项目的 `AGENTS.md`。

### Tool / Skill / Plugin 能力层

- 将测试草案正式安装为 `agent-alpha/home/.agents/skills/managing-knowledge-wikis/SKILL.md`。
- Skill 增加 `.alpha/knowledge-base.json` 的最后创建规则。

### Workspace / Memory / State 持久化层

- 标识跟随项目文件夹保存。
- `raw/wiki/inbox/archive` 结构和原文保护规则保持不变。

## 八、异常处理

- 任一确认框取消：关闭弹层，不创建会话。
- 快速连续确认：临时禁用，只创建一个会话和一条消息。
- 新建会话失败：显示现有错误提示，项目状态不变。
- 会话创建成功但发送失败：保留空会话，显示错误，项目仍为普通项目。
- 用户拒绝 AI 预览：不创建标识。
- 初始化中途失败或没有写权限：报告阻塞，不创建标识。
- `.alpha/` 已存在：只新增标识，不覆盖其他内容。
- 已有标识：不重复初始化。
- 后台读取项目状态失败：保留现有界面，不影响对话。

## 九、测试标准

### 前端单元测试

- 项目按钮顺序、图标和显示条件。
- 两层确认框、鼠标离开关闭和取消行为。
- 连续点击只产生一次初始化请求。
- 初始化会话标题和三段提示词完全一致。
- 自动消息可见并进入普通消息链路。
- 维护面板展开、收缩和执行后保持展开。
- 移除文字插入光标位置且不覆盖草稿。
- 无会话自动创建、有运行任务进入队列。
- 知识库状态改变时，滚动位置、草稿和会话选择不变。

### FastAPI 接口测试

- 标识不存在时返回 `false`，存在时返回 `true`。
- `.alpha/` 存在但没有标识时返回 `false`。
- 中文、空格、长路径和外部项目能够识别。
- 项目路径不存在或暂时无法读取时安全返回 `false`。
- 判断逻辑不能读取工作区之外的路径。
- 新字段兼容旧项目状态。

### Skill 与人工验证

- 空项目和已有文档项目均只在验证完成后创建标识。
- 已生成部分 Wiki 后失败时，不提前创建标识、不覆盖原始资料。
- `.alpha/` 中已有其他文件时，只增加标识文件。
- 重新导入已有知识库时直接显示维护入口。
- 不使用浏览器自动化测试；采用前端单元测试、FastAPI 测试、Skill 校验和人工交互检查。

## 十、验收结果

满足以下条件视为本迭代完成：

1. 普通项目可以通过书本按钮启动知识库初始化对话。
2. AI确认并完成转换前，项目不会被标记为知识库。
3. 标识创建后，界面无刷新、无滚动跳动地切换到维护入口。
4. 增加、移除和全局整理符合已确认的发送方式与确认边界。
5. 自动消息全部可见、可追溯，并复用现有会话执行链路。
6. 正式 Skill 能保证标识是初始化流程最后创建的文件。

## 十一、实施结果（2026-07-23）

本迭代已按上述设计接入 alpha：

- Web 入口层：项目行增加书本改造按钮和两层确认；知识库项目在输入区显示可折叠的“增加、移除、全局整理”入口。按钮尺寸、圆角、颜色和 hover 复用现有项目操作与输入工具栏风格。
- 消息与会话编排层：初始化固定创建“初始化知识库”会话；初始化、增加和全局整理均作为可见普通用户消息发送，并复用现有运行状态、events、日志和消息队列。移除只在当前光标处插入草稿，不自动发送。
- Gateway 控制平面层：项目列表、详情、创建和更新响应增加派生只读字段 `is_knowledge_base`；字段不允许通过项目 PATCH 写入。
- Workspace / Memory / State 持久化层：知识库身份只由工作区 `.alpha/knowledge-base.json` 是否为文件决定，不写入 `app_state.json`；状态更新只合并对应项目对象，不刷新项目顺序、会话详情或消息滚动位置。
- Tool / Skill / Plugin 能力层：正式安装 `managing-knowledge-wikis` Skill，并规定只有原文保护、Wiki、索引、日志、AGENTS.md 和链接全部验证完成后，才能把标识作为最后一个写入动作创建。

实现后的自动验证：

- 正式 Skill 通过官方 `quick_validate.py` 校验。
- 知识库定向测试 22 项通过：前端 10 项，后端与 Skill 12 项。
- 前端完整 Node 测试 55 项通过；TypeScript 与 Vite 生产构建通过。
- 排除 Browser Tool 的完整 pytest 回归 197 项通过。
- 未增加前端依赖、数据库、RAG、新 Agent 通道或“新建知识库”入口。
- 按项目约束未执行浏览器自动化；视觉部分通过样式尺寸、主题变量、窄窗口定位逻辑和生产构建检查，桌面端最终手感保留给实际界面验收。
