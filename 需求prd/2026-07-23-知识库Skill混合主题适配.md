# 2026-07-23 知识库 Skill 混合主题适配

## 背景/原因

已有知识库 Skill 草案能够转换已有项目和初始化空项目，但规则仍隐含“知识库具有一个预设主题”。个人知识库可能同时包含会议纪要、读书笔记、意识科学、人工智能和语文资料，也可能从单领域逐渐扩展为多领域。如果按每份资料的主题不断新建目录，会增加用户决策负担，并削弱跨领域查询和后续结构演化能力。

本次只调整单文件 Skill 草案，不修改 alpha 源码。设计继续遵循 LLM Wiki 的最小模式：保留原始资料、由 Agent 维护 Wiki、用 AGENTS.md 固化规则。

## 具体设计

### 开放的个人知识库

- 不要求初始化时预设单一主题。
- 同时支持单领域、多领域和领域持续增加三种状态。
- 初始化空项目时，用户未指定主题则默认建立开放的个人知识库。
- 转换已有项目时，预览主要领域和资料类型，不把跨度较大的资料强行概括成一个主题。

### 克制的分类方式

- `raw/` 只保存来源，不因主题变化反复移动原文。
- 一份资料可以属于多个领域；关系由资料摘要、索引、标签和 Wiki 页面表达。
- 主分类保持少而稳定；具体内容主题优先使用轻量标签和关联。
- 至少两份资料共同支持、单份资料足够形成独立领域，或用户明确要求时，才建立主题页。
- 无法可靠分类的资料进入“暂未归类”或“跨领域资料”，但仍能正常查询。

### 关联、重复和冲突

- 资料明确支持的跨主题关系可以进入正式页面。
- AI 推测的关系只能标为“待验证关联”或“待探索问题”。
- 重复资料保留来源，综合页合并表达；真实冲突并列观点、来源、时间和证据边界。
- 讲稿、笔记和二次分析不继承其引用论文的可信度；未对照原文不得声称已验证或忠实还原。

### 查询与结构演化

- 分类只用于导航，不限制全库查询；复杂问题可以跨领域查找，暂未归类资料也不能被遗漏。
- 新增和归档资料时只维护直接受影响的页面。
- 标签、导航和明显重复等低风险调整可以直接执行。
- 一级分类变化、大量页面移动或多个综合页拆分合并，需要先给整体预览并等待确认。
- 全库整理只能由用户明确指令或未来按钮触发；普通问答和单份新增不触发。

### Harness 分层位置

- 本次变化位于 Tool / Skill / Plugin 能力层。
- Skill 生成的项目专属规则仍进入 Context / Prompt 组装层。
- `raw/wiki/inbox/archive` 仍属于 Workspace / Memory / State 持久化层。
- 未来“全面整理知识库”按钮属于入口层；按钮只发送显式 Skill 指令，本次不实现前端或接口。

## 验收场景

1. 单领域资料初始化后，继续加入不同领域资料，原文不按主题反复移动，Wiki 能克制地长出新领域。
2. 一开始混合上传会议纪要、读书笔记、研究资料和无法判断的零散记录，AI 不强制单一主题，也不为每份资料创建一级分类。
3. 跨领域问题能够查到多个分类以及暂未归类资料，普通问答不写回 Wiki。
4. 用户明确要求全面整理时，低风险修复直接完成，大规模结构调整先给预览。
