# agent-alpha 路径管理说明

本文只记录当前代码已经实现的路径与环境变量行为，不描述未来方案。

## 1. 四个容易混淆的概念

- `PROJECT_ROOT`：Harness 根目录，即 `agent-alpha`。代码根据自身源码位置计算，不依赖盘符、用户名或启动目录。
- `AGENT_ALPHA_ROOT`：由 `PROJECT_ROOT` 生成并注入子进程的真实环境变量。
- `workspace_root`：当前 Agent Runtime 持有的工作区路径。
- `WORKSPACE_ROOT`：系统提示词中展示 `workspace_root` 的名称，目前不是注入 Bash 的环境变量。

进程当前目录 `cwd` 不是路径真源。现有启动脚本会把 cwd 切到 `agent-alpha`，但打包为 exe 后不能依赖这一巧合。

## 2. workspace 的来源

### Web

- 托管项目：`agent-alpha/workspace/projects/proj_xxx`
- 外部项目：用户选择的任意现有目录
- 项目路径保存在 `state/web/app_state.json`
- 创建会话时，项目路径会复制到会话记录
- Web 启动 Agent 时，将会话记录中的路径传给 `AgentRuntime.workspace_root`

### CLI

- 默认 workspace：`agent-alpha/workspace`
- `/workspace set <path>` 可以切换到其他目录
- 当前 workspace 保存在会话快照中；恢复会话时继续使用该路径

如果未传 workspace，`AgentRuntime` 会退回 `PROJECT_ROOT`。Web 和 CLI 的正常入口都会显式传入 workspace。

## 3. 运行时环境变量

环境变量由 `agent/core/runtime_paths.py` 生成。主要映射如下：

```text
AGENT_ALPHA_ROOT         -> agent-alpha
HOME / USERPROFILE      -> agent-alpha/home
XDG_CONFIG_HOME          -> agent-alpha/config
XDG_CACHE_HOME           -> agent-alpha/cache
XDG_DATA_HOME            -> agent-alpha/data
XDG_STATE_HOME           -> agent-alpha/state
APPDATA                  -> agent-alpha/config/appdata
LOCALAPPDATA             -> agent-alpha/data/localappdata
TMP / TEMP               -> agent-alpha/temp
PIP_CACHE_DIR            -> agent-alpha/cache/pip
UV_CACHE_DIR             -> agent-alpha/cache/uv
UV_TOOL_DIR              -> agent-alpha/tools/uv
UV_TOOL_BIN_DIR          -> agent-alpha/bin
NODE_PATH                -> agent-alpha/config/appdata/npm/node_modules
NPM_CONFIG_PREFIX        -> agent-alpha/config/appdata/npm
NPM_CONFIG_CACHE         -> agent-alpha/cache/npm
PYTHONUSERBASE           -> agent-alpha/home/.local
PYTHONPYCACHEPREFIX      -> agent-alpha/cache/python
HF_HOME                  -> agent-alpha/cache/huggingface
TRANSFORMERS_CACHE       -> agent-alpha/cache/huggingface/transformers
PLAYWRIGHT_BROWSERS_PATH -> agent-alpha/cache/playwright
DOTNET_CLI_HOME          -> agent-alpha/home
CARGO_HOME               -> agent-alpha/cache/cargo
RUSTUP_HOME              -> agent-alpha/cache/rustup
VIRTUAL_ENV              -> agent-alpha/.venv
PYTHONNOUSERSITE         -> 1
```

Windows 还会设置 `HOMEDRIVE`、`HOMEPATH`，并默认设置：

```text
PYTHONUTF8=1
PYTHONIOENCODING=utf-8
```

运行时会清除宿主进程中的 `PYTHONHOME`、`PYTHONPATH` 和 `CONDA_*`，避免宿主 Python 或 Conda 污染 alpha 的 `.venv`。

## 4. 持久环境变量

持久服务变量保存在：

```text
agent-alpha/config/runtime_env.local.json
```

它适合保存 token、cookie、API key、代理和其他服务配置。路径策略变量、Python 环境变量、缓存变量和 `PATH` 不能通过该文件覆盖。

`PYTHONUTF8` 与 `PYTHONIOENCODING` 是例外：允许在持久配置中显式设置。运行时用内部变量 `AGENT_ALPHA_RUNTIME_PROFILE_KEYS` 记录本轮注入的键，重建环境时会先清理上一轮持久变量，避免已删除的配置残留。

## 5. PATH 顺序

PATH 前缀依次为：

1. `agent-alpha/.venv/Scripts`（非 Windows 为 `.venv/bin`）
2. `agent-alpha/bin`
3. npm 全局命令目录
4. `agent-alpha/home/.local/bin`
5. 已存在的 `agent-alpha/home/.local/Python*/Scripts`
6. `agent-alpha/cache/cargo/bin`
7. `agent-alpha/home/.dotnet/tools`
8. 宿主 PATH

路径按当前操作系统规则去重，多次初始化不会重复追加。

## 6. 运行目录

启动时会创建 `home`、`bin`、`skills`、`userfile`、`temp`、`cache`、`tools/uv`、`config`、`data` 和 `state` 等运行目录。

Browser 工具已经实际使用：

```text
state/browser/profiles
state/browser/sessions
state/browser/sockets
state/browser/downloads
state/browser/runtime
state/browser/locks
```

其中 `profiles` 保存持久配置，`runtime` 保存临时运行副本，`sessions` 保存会话元数据，`locks` 用于交互式浏览器互斥。

## 7. Skill、Python 与 Node

Skill 同时扫描：

```text
内置/覆盖：agent-alpha/skills/<name>
第三方：   agent-alpha/home/.agents/skills/<name>
```

同名时 `agent-alpha/skills` 优先。

Python 与 Python CLI 以 `agent-alpha/.venv` 为首选安装位置；pip、uv 和字节码缓存进入 Harness。npm 全局 prefix、缓存和 `NODE_PATH` 已收口到 Harness，不主动创建用户 workspace 的 `package.json` 或 `node_modules`。

pnpm、yarn 和 Go 尚未统一收口，仍可能使用宿主目录。

## 8. 各工具的当前相对路径规则

| 组件 | 相对路径起点 |
| --- | --- |
| Bash | `workspace_root` |
| Web 文件接口 | 项目的 `workspace_path` |
| Browser 状态 | `AGENT_ALPHA_ROOT/state/browser` |
| `read/write/edit/append` | 进程 cwd |
| `glob/grep` 未传或传相对 `path` | `workspace_root` |

Bash 的 `working_dir` 不传时使用 workspace；相对 `working_dir` 只按 workspace 解析；绝对目录只能位于 workspace 或 `AGENT_ALPHA_ROOT` 内。

`glob/grep` 在进入 sandbox 前会把缺省或相对 `path` 解析成 workspace 下的绝对路径；显式绝对路径保持不变，因此仍可读取 `AGENT_ALPHA_ROOT` 或其他允许读取的位置。sandbox 与工具执行使用同一份解析结果。

`read/write/edit/append` 尚未统一绑定 workspace。由于 Web/CLI 当前从 `agent-alpha` 启动，这些工具的相对路径通常会落到 Harness 根目录。

## 9. sandbox 当前边界

- workspace 内：允许读写
- `AGENT_ALPHA_ROOT/agent`：只读
- `AGENT_ALPHA_ROOT/session-log`：只读
- `AGENT_ALPHA_ROOT` 的其他目录：当前策略通常允许读写
- Harness 与 workspace 外：允许读取，拒绝显式写入和删除

Bash 会解析常见重定向、复制、移动、删除、`sed -i`、PowerShell 写入、`cd/pushd`、Git `-C` 和 `--work-tree`。这是命令文本级的尽力识别，不是 Windows ACL 或受限子进程，不能保证识别脚本内部的全部写入。

实际 shell 为 Git Bash、WSL 或普通 Bash 时，Bash 工具会在启动进程前拒绝把输出重定向到 `nul`，并提示改用 `/dev/null`；`cmd` fallback 保留原生 `nul` 语义。

## 10. 启动阶段的例外

`start-agent-alpha.ps1` 使用 `.venv` 启动 CLI，并注入完整运行环境。

`setup-agent-alpha.ps1` 安装依赖前也会构造运行环境，但随后临时把 `TEMP/TMP` 改为系统盘下的 `tmp/agent-alpha-uv`，供 uv 安装阶段使用。因此 setup 期间的临时目录与正常 Runtime 不同。

Web 批处理脚本分别以 `agent-alpha` 和 `agent-alpha/frontend` 作为后端、前端 cwd。

## 11. 当前已知的不一致

1. Bash、Web 文件接口与 `read/write/edit/append` 没有共享同一套相对路径解析。
2. 系统提示词有一句称 npm 全局安装保持宿主语义，与实际 `NPM_CONFIG_PREFIX` 内收行为矛盾。
3. Windows 普通路径 API 会把已有的真实 `nul` 文件当作设备，可能将其大小报告为 0 B。

## 12. 一句话总结

当前代码已经统一 Harness 根目录、Bash 与 `glob/grep` 的 workspace 规则、运行环境变量和主要缓存位置；`read/write/edit/append` 仍依赖进程 cwd。
