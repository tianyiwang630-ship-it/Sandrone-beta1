# agent-alpha 路径管理说明

这份文档说明 `agent-alpha` 当前的路径重定向、目录布局、环境变量注入，以及 Python / npm / Go 的运行边界。

## 1. 总体思路

当前 `agent-alpha` 的路径管理可以概括为：

- 所有实际路径都由运行时定位到的 `WORKSPACE_ROOT` 与 `AGENT_ALPHA_ROOT` 推导，不绑定盘符、用户名或安装位置
- Python 运行环境尽量收敛到 `agent-alpha/.venv`
- 常见用户目录、配置目录、缓存目录、临时目录重定向到 `agent-alpha` 项目内部
- skill 采用双路径扫描：第三方 skill 推荐安装到 `agent-alpha/home/.agents/skills`，`agent-alpha/skills` 用于内置 skill、兼容路径和同名覆盖
- npm / pnpm / yarn / Go 保留宿主机全局语义，不强制重定向到 `agent-alpha`
- sandbox 禁止写出 `agent-alpha` 和当前 workspace 之外，并将 `AGENT_ALPHA_ROOT/agent` 整体设为运行时只读

## 2. 启动时发生什么

环境准备脚本是 [setup-agent-alpha.ps1](setup-agent-alpha.ps1)。
日常启动脚本是 [start-agent-alpha.ps1](start-agent-alpha.ps1)。

首次起环境或依赖变更时，运行 `setup-agent-alpha.ps1`，主要做这些事：

1. 把当前目录切到 `agent-alpha`
2. 检查 `uv` 是否可用
3. 如果不存在 `agent-alpha/.venv`，创建 Python 3.12 虚拟环境
4. 要求 `.venv` 的 Python 版本是 `3.12`
5. 调用 `agent.core.runtime_paths` 创建运行目录并生成运行环境变量
6. 将生成的环境变量注入当前进程
7. 安装依赖和 editable 包：

```text
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
uv pip install --python .venv/Scripts/python.exe -e .
```

日常启动时，运行 `start-agent-alpha.ps1`，主要做这些事：

1. 把当前目录切到 `agent-alpha`
2. 确保存在 `agent-alpha/.venv`
3. 要求 `.venv` 的 Python 版本是 `3.12`
4. 调用 `agent.core.runtime_paths` 创建运行目录并生成运行环境变量
5. 将生成的环境变量注入当前进程
6. 执行：

```text
python -m agent.cli.main
```

这意味着 `agent-alpha` 自身始终假设跑在 `.venv` 中，但日常启动不会重复安装依赖。

## 3. 环境变量重定向

运行时环境变量由 [runtime_paths.py](agent/core/runtime_paths.py) 生成。

下表中的 `agent-alpha` 是逻辑名称；实际值均以启动时从源码位置解析得到的 `AGENT_ALPHA_ROOT` 为基准，不是固定路径。

当前主要重定向如下：

```text
AGENT_ALPHA_ROOT      -> agent-alpha
HOME                  -> agent-alpha/home
USERPROFILE           -> agent-alpha/home
XDG_CONFIG_HOME       -> agent-alpha/config
XDG_CACHE_HOME        -> agent-alpha/cache
XDG_DATA_HOME         -> agent-alpha/data
XDG_STATE_HOME        -> agent-alpha/state
APPDATA               -> agent-alpha/config/appdata
LOCALAPPDATA          -> agent-alpha/data/localappdata
TMP                   -> agent-alpha/temp
TEMP                  -> agent-alpha/temp
PIP_CACHE_DIR         -> agent-alpha/cache/pip
UV_CACHE_DIR          -> agent-alpha/cache/uv
UV_TOOL_DIR           -> agent-alpha/tools/uv
PYTHONUSERBASE        -> agent-alpha/home/.local
PYTHONPYCACHEPREFIX   -> agent-alpha/cache/python
HF_HOME               -> agent-alpha/cache/huggingface
TRANSFORMERS_CACHE    -> agent-alpha/cache/huggingface/transformers
PLAYWRIGHT_BROWSERS_PATH -> agent-alpha/cache/playwright
DOTNET_CLI_HOME       -> agent-alpha/home
CARGO_HOME            -> agent-alpha/cache/cargo
RUSTUP_HOME           -> agent-alpha/cache/rustup
VIRTUAL_ENV           -> agent-alpha/.venv
```

Windows 下还会额外设置：

```text
HOMEDRIVE
HOMEPATH
```

## 4. 持久环境变量

持久环境变量文件是：

```text
agent-alpha/config/runtime_env.local.json
```

这个文件用于保存：

- token
- cookie
- API key
- auth header
- proxy
- 其他服务配置

它会在每次 bash 执行前注入运行环境。

但它不能覆盖路径策略变量。当前被保留、不可从这个文件覆写的变量包括：

- `HOME`
- `USERPROFILE`
- `PATH`
- `TEMP`
- `APPDATA`
- `AGENT_ALPHA_ROOT`
- `XDG_*`
- `VIRTUAL_ENV`
- 以及缓存目录相关变量

## 5. PATH 规则

当前 PATH 前缀顺序是：

1. `agent-alpha/.venv/Scripts` 或 `.venv/bin`
2. `agent-alpha/bin`
3. 已存在的 `agent-alpha/home/.local/Python*/Scripts`
4. 原系统 PATH

因此，`agent-alpha` 会优先找到：

- `.venv` 里的 Python
- `.venv` 里装出来的 CLI，例如 `twitter.exe`、`agent-reach.exe`
- `agent-alpha/bin` 下的本地命令入口
- `pip install --user` 等方式安装到 alpha-local Python user base 的 CLI

## 6. 运行目录结构

启动时会自动确保这些目录存在：

```text
agent-alpha/home
agent-alpha/home/.agents/skills
agent-alpha/home/.local
agent-alpha/bin
agent-alpha/userfile
agent-alpha/skills
agent-alpha/temp
agent-alpha/cache
agent-alpha/cache/pip
agent-alpha/cache/uv
agent-alpha/cache/python
agent-alpha/cache/huggingface/transformers
agent-alpha/cache/playwright
agent-alpha/cache/cargo
agent-alpha/cache/rustup
agent-alpha/tools/uv
agent-alpha/config/appdata
agent-alpha/data/localappdata
agent-alpha/state
agent-alpha/state/browser
agent-alpha/state/browser/profiles
agent-alpha/state/browser/sessions
agent-alpha/state/browser/sockets
agent-alpha/state/browser/downloads
```

可以简单理解为：

- `home`：alpha 自己的 HOME
- `skills`：内置 skill / 兼容 / 同名覆盖目录
- `temp`：临时文件
- `cache`：缓存
- `tools/uv`：uv 相关工具目录
- `state/browser/*`：browser 工具未来使用的状态目录

## 7. skill 路径

当前 skill loader 读取两层路径：

```text
内置/覆盖路径：agent-alpha/skills/<skill-name>
第三方推荐安装路径：agent-alpha/home/.agents/skills/<skill-name>
```

优先级规则是：

- 如果两个地方都有同名 skill
- `agent-alpha/skills/<skill-name>` 优先

因此可以理解为：

- `agent-alpha/home/.agents/skills` 是第三方 skill 的主要安装位置
- `agent-alpha/skills` 更适合正式内置 skill、旧兼容路径或覆盖版本

## 8. Python 环境

当前 Python 路径策略是：

- alpha 自己运行在 `agent-alpha/.venv`
- Python 包安装优先进入 `.venv`
- Python CLI 也优先进入 `.venv`
- `pip` 缓存进入 `agent-alpha/cache/pip`
- `uv` 缓存进入 `agent-alpha/cache/uv`

系统提示词会直接给出当前机器上解析后的 Python 解释器绝对路径。推荐规则是：

```text
<AGENT_ALPHA_ROOT>/.venv/Scripts/python.exe -m pip install ...
uv pip install --python <AGENT_ALPHA_ROOT>/.venv/Scripts/python.exe ...
```

也就是说，规范上已经把 `.venv` 作为 Python 和 Python CLI 的首选目标。

## 9. npm / pnpm / yarn / Go

这几类工具目前保留宿主机全局语义，不做项目内强制收口。

当前策略是：

- `npm install -g ...` 允许
- `pnpm add -g ...` 允许
- `yarn global add ...` 允许
- `go install ...` 允许

当前没有专门重定向这些变量：

- `NPM_CONFIG_PREFIX`
- `GOPATH`
- `GOBIN`
- `GOCACHE`
- `GOMODCACHE`

所以它们的全局安装结果仍然可能落到宿主机自己的全局目录，而不是 `agent-alpha` 内。

## 10. bash 工具运行规则

bash 工具定义在 [bash_tool.py](agent/tools/bash_tool.py)。

当前行为是：

- 不传 `working_dir` 时，命令在当前 `WORKSPACE_ROOT` 执行
- 相对 `working_dir` 只按 `WORKSPACE_ROOT` 解析，不会回退到 Harness
- 访问 Harness 时必须传位于 `AGENT_ALPHA_ROOT` 内的绝对 `working_dir`
- 绝对 `working_dir` 只能位于 `WORKSPACE_ROOT` 或 `AGENT_ALPHA_ROOT` 内，并且必须是已存在目录
- 每次执行前重新构造 runtime env
- 运行 shell 时带上项目内重定向后的环境变量
- 工具结果返回规范化后的实际 `working_dir`

所以 cwd 改到 workspace 只改变相对文件路径的起点，不改变 HOME、TEMP、缓存、Skill 和 Python 环境的 Harness 重定向。

这些规则只在 Bash 工具 schema 中向 AI 说明，系统提示词不重复维护另一份规则。

## 11. sandbox 与路径边界

路径边界主要由 [path_policy.py](agent/core/path_policy.py) 和 [sandbox_guard.py](agent/core/sandbox_guard.py) 控制。

当前规则可以概括为：

- `workspace` 内：读写允许
- `agent-alpha` 项目内：读允许，运行目录和第三方 Skill 目录按现有规则可写
- `AGENT_ALPHA_ROOT/agent`：允许读，无条件禁止写入和删除；自动权限和用户批准都不能放行
- `agent-alpha` 外部：读取允许，写入和删除拒绝

保护覆盖内置文件工具，以及可以解析出目标路径的 Bash 重定向、`tee`、`sed -i`、复制、移动、删除和 PowerShell 写入。`cd` / `pushd` 前缀与 Git `-C` / `--work-tree` 也会先换算成真实 cwd；Git 批量恢复或补丁只要可能覆盖 Agent 源码就直接拒绝。路径会先结合实际 cwd 做规范化，因此绝对路径、相对路径和 `..` 最终采用同一判断。

仍可写的 Harness 运行目录包括：

```text
<AGENT_ALPHA_ROOT>/cache
<AGENT_ALPHA_ROOT>/temp
<AGENT_ALPHA_ROOT>/.venv
<AGENT_ALPHA_ROOT>/home/.agents/skills
```

外部已安装 CLI / exe 的规则是：

- 允许执行 `agent-alpha` 外部的已安装 CLI / exe
- 允许调用 npm / Go 全局工具位置里的命令
- 禁止通过参数、重定向、复制、移动、删除等方式显式写入 `agent-alpha` 和当前 workspace 外部

例如：

```text
C:/Users/<user>/go/bin/agent-browser.exe --version
C:/Users/<user>/AppData/Roaming/npm/agent-browser.cmd open https://example.com
```

这类“只执行外部工具”的命令允许。

```text
C:/Users/<user>/go/bin/agent-browser.exe --output C:/Users/<user>/Desktop/page.json
agent-browser > C:/Users/<user>/Desktop/page.json
```

这类“明确写外部文件”的命令会被拒绝。

也就是说，现阶段 sandbox 最核心的目标是：

- 不让 agent 直接写到 `agent-alpha` 外部
- 不让运行时 agent 修改 `AGENT_ALPHA_ROOT/agent`

这是策略级保护，不是 Windows ACL 或受限子进程，不承诺阻止恶意 Python/Node 脚本主动绕过。

## 12. 当前状态下需要注意的点

1. Python 的规范已经偏向 `.venv`，但历史上仍可能留下 `pipx` 或 `tools/uv` 的旧痕迹。
2. npm / Go 还没有内收进 `agent-alpha`，仍按宿主机规则工作。
3. `agent-alpha/home`、`agent-alpha/cache`、`agent-alpha/state` 这些目录本质上属于运行态目录，不等于源码目录。
4. browser 工具已经预留了 `state/browser/*` 目录，但具体怎么用还需要后续工具实现来决定。
5. 本次不识别、创建或维护用户项目自己的 `.venv`，但没有封死以后扩展项目级依赖管理的入口。

## 13. 一句话总结

当前 `agent-alpha` 的路径管理是：

- Python 和大多数运行时目录尽量项目内化
- Bash 默认从 workspace 执行，相对 `working_dir` 只认 workspace；访问 Harness 使用运行时给出的绝对路径
- 第三方 skill 主要安装到 `agent-alpha/home/.agents/skills`，加载时同时扫描 `agent-alpha/skills`
- npm / Go 继续走宿主机全局语义
- `agent-alpha/agent` 对运行时只读，其余写入继续受 workspace/Harness 边界约束
