# 2026-09-20 Windows EXE 安装包

## 背景/原因

用户日常直接运行开发版，需要随时修改代码并快速验证；发布时则希望从同一项目生成可分发的 Windows 安装包。项目结构需要支持双模式，但开发版的功能、执行逻辑、数据位置和启动习惯必须保持兼容。

## 具体设计

- 入口层：Electron 根据 `app.isPackaged` 选择源码环境或随包运行环境，保留单实例、8787 冲突检查及退出清理。
- 持久化与资源层：安装资源与 `%LOCALAPPDATA%/AgentAlpha` 用户数据分开；开发版仍使用项目目录。内置资源只读，生成配置和日志写用户目录。
- 能力层：Browser Harness 公共执行器保持调用 EXE。安装包不复制开发机 uv 生成的启动器；发布版首次启动由随包 uv、Python 与离线 wheel 生成本机 EXE，校验 0.1.13，后续复用。
- 发布流程：NSIS x64 当前用户安装，桌面和开始菜单入口；包含独立后端和浏览器 Python、Chrome for Testing、固定 MCP、前端与 Skill。开发版 MCP 配置保持原样，发布版启动时覆盖为随包执行器。
- 构建在 `temp/package-stage` 完成，下载缓存可复用，最终 EXE 与版本/哈希清单输出到 `release`。不携带密钥、现有会话、工作区和浏览器资料。
- 不增加自动更新、签名、ARM64 或迁移；卸载保留用户数据。模型和搜索服务仍按原行为访问网络。

## 验证

后端 364 项、前端 108 项测试及 TypeScript/生产构建通过。已实际验证限制 PATH 后由随包 uv 离线生成 Browser Harness EXE，并在后续启动中复用。完成临时安装、重启、卸载、重装和再次启动验收，验证用户数据保留、应用退出及后端进程清理。最终 Setup.exe 为 372.73MB；构建流程以 700MB 为目标提醒线、900MB 为拒绝发布的硬上限。安装与生命周期验收结果记录于开发日志。
