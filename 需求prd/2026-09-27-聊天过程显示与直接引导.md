# 2026-09-27：聊天过程显示与直接引导

## 背景与目的

模型运行时间较长时，用户需要能看见自己刚发出的消息、模型已经给出的回答，以及正在执行的工具。当前页面有三类体验问题：伴随工具调用的模型文字容易被收进工具区域；运行中的直接引导没有及时出现在对话中；用户只能把新消息排进队列，不能直接把某条已排队消息转为当前任务的引导。

聊天界面的文字密度和绿色强调也与用户提供的 Codex 桌面截图不一致。用户还需要从长对话中快速找到旧消息。

目标是让消息归属、执行进度和队列状态都能即时辨认，并提供可预览、可点击的轮次导航。此需求针对当前 Windows 开发版、Web 和 Electron 共用前端。后续 Mac 端可依据本 PRD 的产品行为和实现链路改写平台部分。

## 设计方案

### 对话、回答与工具

- 历史消息、当前会话的运行事件和本地待发送消息合并为同一条有序对话。使用消息 ID 关联已送达和本地待处理副本；相同文字但不同 ID 的消息保留为两条。
- 带工具调用的模型正文与普通模型回答一样，放在 AI 正文区域并按 Markdown 显示。工具名称、参数、执行状态和结果放在独立的工具卡片中。
- 正文在当前任务运行中持续更新。历史正文和流式正文交接时不得闪回、重复或遗失。中断以后保留已显示的正文和已完成的工具记录；没有结果的工具标明未收到结果。
- 如果用户在模型生成途中中断，已经收到的部分回答仍写入对话历史，并标记为中断前已生成内容；后续刷新或重新打开对话时仍能看到。
- 直接引导送出后马上显示为一条用户消息，依次呈现“发送中”“等待处理”“已接收”。“已接收”表示消息已进入 Agent 上下文，不代表该任务已完成。根据当前轮事件与消息 ID 对齐状态；历史已包含该 ID 时不再显示乐观副本。
- 若网络错误导致客户端不确定请求是否送达，消息显示“发送结果待确认”并保留原消息 ID；同一会话、同一草稿的重试跨刷新和任务运行切换继续复用该 ID，服务端按 ID 去重。服务端明确拒绝或确认接收后才清除该尝试 ID。
- 页面刷新时，服务端会话详情应包含已接受但仍在邮箱中等待处理的直接引导，按消息 ID 去重并继续显示等待状态。
- 切换会话、轮询运行事件、刷新历史和任务结束不得把消息移动到工具区域、重复显示或串到其他会话。用户滚动查看旧消息时，不因实时更新而强制跳到底部。

### 队列消息直接引导

- 正常运行期间，输入框按回车或发送按钮继续将消息加入队列。输入框的“直接引导”按钮继续把新草稿投递给当前任务。
- 每条排队消息新增“直接引导”按钮。点击只投递该行内容，不读取或清空输入框，不改动其他队列行及其顺序。
- 只有当前会话的聊天任务处于运行状态且具有当前运行 ID 时可操作。上下文压缩、停止中、尚未拿到运行 ID 或任务结束时禁用。
- 正在提交的那条队列行临时禁用拖动和撤回，避免用户把尚未确认的发送误认为已经取消。
- 请求期间锁住当前行，避免重复点击和队列自动取走。服务端接受后，此消息从队列移除并成为对话里的直接引导消息；其他行顺序不变。
- 请求失败时，队列行和顺序保留，草稿入口内容保留，界面提示失败原因。若任务在用户点击到服务端处理之间结束，服务端拒绝以旧运行 ID 引导，消息仍留在队列中，不能因此意外启动新任务。
- 客户端为直接引导提供稳定消息 ID。相同 ID 的网络重试返回原收件回执，不在邮箱中重复插入同一消息。

### 左侧轮次导航

- 左侧每个小横杠对应一轮用户输入以及该轮 AI 内容。用户的直接引导同样形成一轮定位点；工具卡片不单独生成定位点。
- 悬停或键盘聚焦时显示预览卡：用户内容最多两行，AI 内容最多三行，过长以省略号截断；暂无 AI 正文时显示当前处理状态。
- 点击后滚动到对应用户消息。当前所在轮次加深，悬停或聚焦的横杠变长。导航固定在聊天区域左侧并拥有独立滚动，右侧正文滚动条保持原位。
- 正文滚动切换当前轮次时，左侧导航自动滚动到该轮横杠；该动作只滚动左侧导航自身。
- 预览卡与横杠在窄聊天区和文件侧栏打开时仍可用；预览卡位于独立滚动条之外，不被横杠列表裁剪；导航不覆盖正文起始区域，也不拦截正文滚动。

### 字体与配色

参考本机 Codex Windows 桌面版 `26.924.2738.0` 的浅色界面及用户截图中的聊天样式，而非单独复制网页组件。桌面聊天字号代码默认值为 13px，代码文字默认值为 12px，正文行高是字号的 1.625 倍；代码支持用户字号覆盖，因此验收以应用内可读密度和对应默认值为准。

- 字体使用跨平台系统字体栈，Windows 优先 Segoe UI，Mac 优先系统字体，中文回退至系统中文字体。
- 主内容白色，侧栏、卡片和选中态为浅灰色，正文深灰，辅助文字中灰。浅色参考值包括 `#ffffff`、`#f9f9f9`、`#ededed` 和 `#1a1c1f`。
- 用中性深灰作为通用强调色；错误提示保留红色等语义色。不使用绿色作为通用按钮、选中或页面强调色。
- 回答正文为 13px、行高 1.625；代码为 12px。标题按正文比例缩放，避免标题继续占据过多页面空间。

## Windows 实施指引

### 分层与数据流

本需求涉及：

1. **入口层 / Channel Layer**：React 页面显示对话、状态、队列、预览卡和定位导航。Web 与 Electron 共用 `agent-alpha/frontend/src`。
2. **Gateway 控制平面层**：FastAPI 校验当前运行 ID 和聊天请求，并返回引导回执。
3. **消息与会话编排层**：收件箱接收直接引导，Agent Loop 在现有安全输入边界取出消息并将消息 ID 写入历史事件。
4. **Workspace / Memory / State 持久化层**：会话事件和历史为显示恢复提供消息 ID；前端消息队列仍为当前 Web/Electron 窗口内的暂存状态，不宣称跨重启持久化。

典型链路：

```text
App.tsx 草稿/队列行
  → frontend/src/api/client.ts
  → POST /api/chat
  → routes/chat.py 与 ChatRequest
  → AgentManager.submit_chat
  → Collaboration.deliver（邮箱中按 message_id 去重）
  → Agent Loop 在模型/工具交换边界 take_inputs
  → 事件与会话历史含 _message_id；中断时从 assistant_delta 事件恢复部分正文
  → GET /api/sessions/{session_id} 返回历史与未处理邮箱消息
  → 前端按 message_id 合并并呈现回答状态、队列和轮次导航
```

实时回答沿用会话事件接口：`GET /api/sessions/{session_id}/events`。新任务的开始、完成和停止状态沿用现有 `/api/chat` 运行状态接口。正常发送模式继续按原队列/新任务语义工作。

### 接口及字段

`POST /api/chat` 在现有请求字段上支持：

```json
{
  "session_id": "会话标识",
  "message": "引导内容",
  "mode": "steer",
  "expected_request_id": "用户当前看到的运行标识",
  "client_message_id": "该条本地消息的稳定标识"
}
```

直接引导响应包含现有的 `request_id`、`session_id` 和 `message_id`。有 `expected_request_id` 的引导只接受匹配且仍在运行的任务；运行结束或切换后返回冲突，由客户端保留该队列行。重复 `client_message_id` 只返回既有邮箱回执。旧客户端不带两个可选字段时保持已有行为。

会话详情中的消息增加公开字段 `message_id`，映射持久事件/运行历史中的 `_message_id`；`partial` 标记中断时恢复的部分回答，`delivery_status` 表示仍在邮箱中的直接引导等待状态。前端的发送中状态只保存在本地 UI，不写入模型上下文；接受后依靠服务端事件中同一 ID 切换为已接收，进入会话历史后移除本地副本。

### 代码位置与本机路径

仓库根目录：

```text
D:\files\demo\0312-newagent - 交互试验beta
```

主要代码和运行位置：

- `agent-alpha\frontend\src\App.tsx`：聊天轮次、事件合并、运行中状态、直接引导、排队行、导航和悬停预览。
- `agent-alpha\frontend\src\steeringAttempts.ts`：本地待确认直接引导的会话级消息 ID 保存、跨运行重试及旧缓存迁移。
- `agent-alpha\frontend\src\chatPresentation.ts`：历史/待处理消息去重与工具显示模型。
- `agent-alpha\frontend\src\styles.css`：Codex 浅色主题、聊天排版、横杠导航与队列按钮样式。
- `agent-alpha\frontend\src\api\client.ts`、`src\types\index.ts`：聊天请求和消息类型。
- `agent-alpha\frontend\tests\steeringAttempts.test.mjs`：跨任务重试、确认后清理和旧缓存迁移测试。
- `agent-alpha\agent\server\routes\chat.py`、`server\models.py`：FastAPI 聊天请求与响应。
- `agent-alpha\agent\server\agent_manager.py`：运行 ID 检查、邮箱投递协调。
- `agent-alpha\agent\core\collaboration.py`：邮箱消息 ID、重复投递保护、消息取出和确认。
- `agent-alpha\agent\server\routes\sessions.py`：会话历史组装、从 `assistant_delta` 和 `llm_request_interrupted` 事件恢复中断前正文，并将待处理的直接引导带入会话详情。
- `agent-alpha\agent\core\session_events.py`：聊天流式事件及 `_message_id` 持久化；历史事件迁移清理时保留被中断请求的最后一段流式正文。
- 运行事件目录为 `agent-alpha\session-log\events`；会话历史通过现有 SessionStore 保存。
- 中间与临时测试产物放 `agent-alpha\temp`，不要在工作区根目录散落文件。

### 开发版与 EXE

日常开发在 Windows 使用项目已有 Node/npm 依赖，于 `agent-alpha\frontend` 执行 `npm run dev`；`npm run build` 执行 TypeScript 检查和 Vite 生产构建。Electron 桌面版读取同一套前端构建。经用户决定发布时，由 `npm run package:win` 调用 `frontend\scripts\package-windows.ps1` 生成 Windows 安装包；本需求自身不要求每次开发后自动打包。

## 验收标准

- AI 在工具调用前说明计划时，说明文字显示在 AI 正文，不进入工具卡片；调用名称、参数和输出仍在独立工具卡片中。
- 运行中输入的引导立即出现在聊天；事件带有其消息 ID 后状态变为“已接收”，历史加载后只有一份记录。
- 运行中按回车的消息留在队列；点击某条“直接引导”只投递这一条，其他行和输入草稿不变，投递成功后该行消失且对话显示引导。
- 中断回答后重新打开会话，已经收到的部分正文仍可见；刷新时邮箱中尚未处理的直接引导仍显示且不重复。
- 悬停预览不被导航滚动区裁切；直接引导请求期间对应队列行不能拖动或撤回。
- 快速连点、相同文本不同消息、事件重复、请求失败重试和任务结束竞争均不会重复投递或静默丢失；结束竞争失败时队列行仍在原位。
- 请求已到服务端但响应丢失时，直接引导显示待确认；用同一草稿重试只产生一条消息。
- 旧任务结束后，该引导已进入邮箱并在新任务中待处理时，重试仍复用原消息 ID；确认接收或明确拒绝后，用户之后再次发送相同内容会生成新 ID。
- 点击每个横杠准确定位其对应用户消息；悬停预览包含用户内容和 AI 内容，截断、键盘聚焦、很多对话及打开文件侧栏时均可操作。
- 正文滚动改变当前轮次后，该轮横杠保持在左侧导航可视范围内，且不移动右侧正文滚动位置。
- 右侧连续滚动、左侧独立导航、滚动位置恢复和自动跟随行为互不破坏。
- 主聊天视觉采用白色、浅灰、深灰及 Codex 系统字体规则；回答正文默认 13px、代码默认 12px；普通界面不以绿色作强调色。
