# 2026-07-23 知识库 Skill 草案

## 背景/原因

用户希望先用 alpha 现有的通用文件、联网和对话能力验证一个最小知识库场景，再决定是否改造产品功能。目标类似轻量版 NotebookLM：

- 把已有文档项目转换成可查询的 Wiki；
- 初始化空白知识库后持续加入资料；
- 普通问答默认只读；
- 联网搜索和下载后由用户决定是否入库；
- 支持新增、用户审阅和可恢复归档。

前期手工试验暴露了过早固定目录、把同源格式重复计为证据、普通问答可能写回、翻译与原文归属混淆、相对链接假验证等问题。因此先把已确认流程沉淀为单文件 Skill 草案，不修改 alpha 后端或前端。

## 具体设计

### 能力边界

- Skill 只能被用户点名或未来按钮显式调用，不能自动触发。
- 不引入 qmd、BM25、向量数据库、RAG 服务或 Obsidian。
- 复用 alpha 已有的查找、读取、写入、编辑、移动和联网工具。
- 本轮只生成草案文档，不注册正式 Skill，不修改 Agent Runtime。

### 最小目录

知识库固定 `inbox/`、`raw/`、`wiki/` 和 `archive/` 四类状态目录；Wiki 只固定 `index.md`、`log.md` 和 `sources/`。领域主题目录由 Agent 根据实际资料动态决定。

### 初始化与转换

- 空项目：确认主题后建立最小结构。
- 已有项目：先只读盘点，按逻辑资料组提出建议入库、排除、配套和待确认清单；用户确认后才移动文档并生成 Wiki。
- 建议入库资料默认移动到 `raw/`，不入库文件留在原位置。
- 同一论文的 PDF、TXT、翻译等按逻辑资料组处理，不重复计算证据。

### AGENTS.md

Skill 在初始化时生成项目专属 `AGENTS.md`。如果用户已有同名文件，将其顺延改名为 `AGENTS-1.md`、`AGENTS-2.md` 等，并明确告知旧文件不再被 alpha 自动加载。新文件包含目录职责、原文保护、查询、写入、来源、联网和更新规则。生成后提醒用户新建会话。

### 查询与维护

- 普通查询先读 Wiki，必要时回查 `raw/`，默认不写入。
- 联网结果先展示；下载文件进入 `inbox/`，用户明确选择后才入库。
- 简单新增直接执行；来源不明、重复、冲突或影响多个页面时先确认。
- “删除”默认执行可恢复归档，并在确认后撤回只由该资料支持的活跃结论。
- 用户批评先核查来源，再提出修订方案。
- 巡检从每个 Markdown 文件所在目录解析相对链接。

### Harness 分层位置

- 主要变化属于 Tool / Skill / Plugin 能力层。
- Skill 生成的 `AGENTS.md` 进入 Context / Prompt 组装层。
- `inbox/raw/wiki/archive` 属于 Workspace / Memory / State 持久化层。
- 后续按钮、接口和状态展示属于入口层与 Gateway 层，本次不实施。

## 验收场景

1. 在 `知识库测试3` 中转换已有的11篇文档，完成查询、联网搜索、选择入库和归档。
2. 在空文件夹中初始化知识库并加入数篇文档；后续维护流程复用场景一。
