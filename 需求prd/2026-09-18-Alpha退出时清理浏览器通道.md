# 2026-09-18 Alpha 退出时清理浏览器通道

> 状态：已实施并通过自动测试。

## 背景/原因

Electron退出时直接结束自己启动的FastAPI进程，可能使FastAPI生命周期来不及关闭Alpha专属Chrome和Browser Harness daemon，留下仍可连接的调试端口。与此同时，Agent遇到登录页时可能持续等待或重试，没有及时把浏览器交给用户。

本次以最小改动修复退出编排，并压缩Browser Harness Skill中的人工登录规则。不改变模型可见工具、浏览器资料目录、Agent Loop或会话格式。

## 具体设计

### Tool / Skill / Plugin 能力层

- 登录、MFA、验证码、不安全浏览器提示或连续两次相同登录状态出现时，Agent停止重试。
- 用户主动要求接管，或工具返回 `user_action_required` 时，Agent只给出一条简短指引：在Alpha浏览器的 `chrome://inspect/#remote-debugging` 中关闭远程调试、完成登录、重新开启，然后回复“继续”。
- 用户回复“继续”后，Agent重新调用原工具并检查页面状态。

### Agent Runtime / Harness 层

- 浏览器关闭不再依赖当前后端进程是否已经成功执行过浏览器工具。
- 退出时始终检查Alpha专属资料目录的健康端口：存在时通过CDP `Browser.close` 关闭专属浏览器；随后调用Browser Harness官方 `--reload` 停止daemon。
- 没有调试端口时只停止daemon，不按进程名强杀处于人工登录状态的Chrome，也不删除登录资料。
- `shutdown_browser_harness_runtime()` 在进程内尚无运行实例时创建同一项目根对应的运行对象，从而能够清理上一次进程留下的专属端口和daemon。

### Gateway 控制平面层

- 新增内部REST接口 `DELETE /api/runtime/browser`，只复用共享运行层的关闭函数，不在路由中实现浏览器逻辑。
- 接口可重复调用；浏览器已经关闭或无端口时保持安全。

### 入口层 / Channel Layer

- Electron收到退出事件后先调用浏览器关闭接口，最长等待5秒，再结束自己启动的FastAPI后端。
- 清理失败或超时不阻塞应用退出。
- Electron复用外部启动的同项目后端时，仍请求清理共享浏览器，但不结束不属于自己的后端进程。
- 启动失败路径继续按原方式退出，不增加前端按钮或页面状态。

## 异常与边界

- 后端不可达、响应非成功、返回内容无效或超过5秒：视为清理失败，Electron仍继续退出。
- 浏览器通道正忙：运行层使用现有共享锁等待；超时后返回失败，不强杀浏览器任务。
- 人工登录期间远程调试已关闭：没有开放端口，只停止daemon并保留普通Alpha Chrome窗口。
- 日常Chrome不使用Alpha专属资料目录，关闭链路不会扫描或结束其进程。
- 断电、任务管理器强杀Electron或操作系统强制终止时，无法保证执行退出回调；下次启动仍通过专属端口检查处理残留。

## 验收标准

- Electron正常退出时，先请求浏览器清理，再结束自有后端。
- 健康Alpha专属端口即使尚未被当前后端成功使用，也会被关闭。
- 无端口时仅停止daemon，不误关日常Chrome。
- 外部后端不会被Electron结束。
- 清理失败不会导致Electron无法退出。
- `browser_harness_exec` 的名称、参数和注册方式保持不变。
- 自动测试不启动真实浏览器。

## 本次明确不做

- 不新增浏览器工具、工具参数、数据库、MCP或前端接管按钮。
- 不按浏览器进程名批量结束Chrome。
- 不在人工登录状态下强杀无调试端口的Chrome。
- 不解决断电和操作系统强杀场景。
