# 对话轮次导航定位与滚动优化

## 背景 / 原因

聊天区左侧的轮次横杠用于快速查看和定位历史对话。当前点击横杠时，页面可能滚动到不正确的区域；横杠列表始终从顶部开始排列，较短对话时视觉重心偏上，长对话的导航也不容易辨认和操作。

## 目标

让用户能从左侧导航快速回到任意一轮对话；导航位置和样式清楚，并能在对话很多时继续使用。消息区与左侧导航分别滚动，互不干扰。

## 具体设计

### 轮次定位

- 点击某个横杠后，将对应轮次的用户消息立即滚到聊天消息区顶部附近，并更新当前轮次标记。
- 定位只滚动聊天消息列表，不应滚动整个页面、导航轨道或输入区。
- 保留鼠标悬停和键盘聚焦时显示的用户消息及模型回答预览。
- 用户手动滚动消息区时，当前轮次标记继续跟随可视位置更新。
- 后台刷新聊天内容时，应保留内容更新前用户最新的滚动位置；不能用刷新请求发出时的位置覆盖等待期间的点击跳转或手动滚动。切换会话时仍恢复目标会话自己的历史位置。

### 导航位置和长对话

- 左侧导航轨道在聊天消息可视区域内垂直居中，不覆盖输入区。
- 对话轮数较少且能完整显示时，横杠组在轨道中垂直居中。
- 对话轮数较多时，轨道限制在可视高度内并显示细滚动条；滚动该轨道只移动横杠列表，不移动聊天消息。
- 当前轮次标记移出轨道可视范围时，自动将其滚回可见范围。
- 保留聊天消息区右侧原有滚动条。左右滚动条分别控制各自区域。

### 视觉样式

- 参考 Codex 的简洁浅灰界面，以中性灰色显示非当前横杠，以深灰显示当前横杠。
- 横杠默认短而细；鼠标悬停或键盘聚焦时，仅对应的横杠伸长。当前轮次用稍深灰色识别，但不默认伸长。
- 导航滚动条使用细窄的灰色滑块，与消息区滚动条在位置和操作上区分开。

### 前端实现指引

- 入口属于前端展示层，主要涉及 Windows 开发版代码 `agent-alpha/frontend/src/App.tsx` 和 `agent-alpha/frontend/src/styles.css`。
- 横杠定位应调用聊天消息列表自己的滚动接口，不直接对目标消息使用会连带滚动其他容器的全局定位方式。滚动几何计算可复用 `agent-alpha/frontend/src/chatScroll.ts`。
- 导航轨道应以消息列表所在的网格区域为定位范围，使它随消息视口高度变化，同时保持独立滚动。

## 验收标准

- 点击任意横杠后，对应轮次进入聊天消息区可视范围，输入区和页面外层不发生跳动。
- 点击靠近列表顶部或底部的轮次都能正确定位；消息列表带有边框时定位仍正确。
- 少量轮次在消息视口中间排列；大量轮次可通过左侧轨道滚动访问，当前轮次会自动保持可见。
- 滚动左侧轨道不会带动聊天消息区；滚动聊天消息区不会带动左侧轨道。
- 鼠标悬停、键盘聚焦预览及原有的当前轮次跟随能力仍可使用。
- 刷新请求尚未返回时点击横杠或手动滚动（包括滚到顶部），返回后不回弹；切换会话后的旧响应不影响当前会话的位置。
