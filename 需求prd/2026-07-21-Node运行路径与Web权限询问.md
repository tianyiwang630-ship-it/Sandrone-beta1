# Node 运行路径与 Web 权限询问

## 背景/原因

Bash 默认 cwd 改为用户 workspace 后，npm 全局包虽然安装在 Harness 内，但 Node 没有 `NODE_PATH`，导致 `require('docx')` 等调用找不到已经安装的模块。与此同时，Web 的“询问权限”模式仍复用 CLI 的终端 `input()`，浏览器没有接收和回复权限请求的通道，任务会一直等待。

## 具体设计

- Agent Runtime / Harness 层根据运行时解析出的 `AGENT_ALPHA_ROOT` 设置 npm prefix、缓存、`NODE_PATH`、uv 工具入口及相关 PATH，不使用固定盘符或用户名；不主动创建用户项目依赖。
- 权限 / 沙箱 / 安全层继续先执行 sandbox 判定；只有 `ask` 决策进入权限协调器，`deny` 不可被人工审批绕过，`auto` 模式维持现有自动放行语义。
- Gateway 控制平面层把待审批信息附加到 chat run 状态，并提供一次性决策接口；审批状态只存在当前服务进程，等待 10 分钟后自动拒绝，中止、删除或释放 Agent 时立即清理。
- Web 入口层在当前会话输入区上方显示权限卡片，提供“允许一次、拒绝、追加说明后重试”；其他会话通过侧栏标记提示。页面刷新后沿用现有 run 状态轮询恢复卡片，不新增 WebSocket 或 SSE。
- CLI 入口继续使用终端权限询问，不受 Web 改造影响。

## 接口

- `GET /api/chat/status/{request_id}` 和 session active run 状态增加可空的 `pending_permission`。
- `POST /api/chat/permissions/{permission_id}/decision` 接收 `allow_once`、`deny`、`retry_with_context`；追加说明方式必须提供非空 `instruction`。
