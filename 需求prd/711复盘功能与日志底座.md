# 711 复盘功能与日志底座

## 背景/原因

当前会话系统已经能管理项目、会话和实时过程，但用户和 AI 都缺少一个“回头看”的正式入口：

- 用户聊了很久之后，很难快速知道这个项目到底做了什么、为什么这么做、卡在哪里、现在到哪一步。
- AI 接手老项目时，也缺少一份专门面向 AI 的“坑位说明”和用户偏好说明。
- 现有 `session`、`event`、`log` 三类材料职责不够清晰：Web 没有完整实时 log，event 过胖，`session-log` 也没有面向 Agent 的读写边界。

因此这次迭代要同时解决两件事：

1. 补齐日志底座，让 `session / event / log` 各自承担明确职责。
2. 在尽量少改动现有架构的前提下，增加“复盘此会话 / 复盘此项目”的完整用户链路。

## 具体设计

### 一、日志职责分层

- `session`
  - 作为正式会话状态与继续对话上下文。
  - 用于用户继续聊天、恢复 runtime history、保存最终可展示历史。

- `event`
  - 作为 Web 实时过程展示材料。
  - 作为精简复盘材料。
  - 作为硬崩溃后的精简恢复依据。
  - 对工具参数和工具结果做独立瘦身，不反向修改 session history。

- `log`
  - 作为实时调试黑匣子。
  - 记录比 session/event 更完整的原始信息。
  - 供复盘在 event 信息不足时补读。

### 二、日志底座改造

- Web 与 CLI 统一写入 `session-log/logs/<session_id>.jsonl`。
- log 在 session/event 截断前记录用户消息、AI 回复、工具调用、原始工具结果、模型重试、压缩、中断和错误。
- log 单条工具结果限制为 `128,000` 字符、`2,000` 行；超限记录原始长度与保留长度。
- event 使用独立副本做二次截断：
  - 工具参数：`2,000` 字符、`20` 行。
  - 工具结果：`4,000` 字符、`60` 行。
  - 用户消息和 AI 最终回复不增加 event 专属限制。
- 运行中保留 `assistant_delta` 给 Web 做实时展示；成功写入 session 后，清理该轮 `assistant_delta`、正常请求开始和成功事件。
- 失败、可恢复或未结束运行不清理，以便继续从 event 恢复精简现场。
- 历史 event 做一次幂等迁移：瘦身旧工具正文，并清掉已成功运行的低价值流式事件。

### 三、权限与沙箱

- 整个 `session-log` 对 Agent 工具只读。
- `sessions` 和 `events` 可正常读取。
- `logs` 可正常读取，用于 debug 和复盘补充事实。
- 不把 log 读取权限和复盘后端计算出的路径绑定；后端只负责在任务提示词里列出推荐读取的 event/log 路径。
- Runtime 内部的 SessionStore、EventWriter、LogWriter 不受这层 Agent 沙箱限制，仍可正常写入。

### 四、复盘用户链路

- 入口放在输入框左下角 `+` 菜单，位于“手动压缩上下文”下：
  - `复盘此会话`
  - `复盘此项目`

- 点击后流程如下：
  1. 前端调用 `POST /api/sessions/retrospective`。
  2. 后端按 `project_id` 和 `scope=session|project` 计算来源 event/log 路径。
  3. 后端自动创建一个新的普通会话。
  4. 系统自动发送一条带 `[系统复盘任务]` 标记的消息。
  5. 新会话自动启动现有聊天流程。
  6. 前端切换到新会话，沿用现有轮询展示运行状态。

- 单会话复盘需要 `source_session_id`。
- 项目复盘按 `project_id` 筛选普通及归档会话，不混入其他项目。
- 运行中的来源会话允许复盘，但要提示“以读取时已落盘内容为准”。

### 五、复盘 Skill

- 新增内置 `retrospective` Skill，只在显式调用时触发。
- Skill 要求：
  - 显式加载 `planwithfile`。
  - 优先读取 event，信息不足时才读取任务列出的对应 log。
  - 项目复盘时跳过首条用户消息带 `[系统复盘任务]` 的历史复盘会话。
  - 不读取旧复盘报告作为来源材料。
  - 过程文件写入 `复盘/.过程/<时间-范围-ID>/`。
  - 输出两个正式报告：
    - `复盘/<时间-范围-ID>-工作复盘.md`
    - `复盘/<时间-范围-ID>-AI交接报告.md`

- 最终回复要明确告诉用户两个文件路径，并提示：
  - “需要让其他 AI 阅读时，直接让它读取 AI交接报告即可。”

### 六、已确认取舍

- 不新增 `purpose` 字段。
- 不新增新的 Agent 类型。
- 不改变现有多 Agent 架构。
- 不由后端检查最终复盘报告文件是否真的存在，交给 Skill 约束。
- AI 交接报告不会自动载入会话或全局记忆；用户如果要让 AI 看，需要显式让 AI 读取。
