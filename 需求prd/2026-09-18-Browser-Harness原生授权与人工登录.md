# 2026-09-18 Browser Harness 原生授权与人工登录

> 状态：已实施并通过自动测试。

## 背景/原因

Browser Harness 初版适配使用 Alpha 专属浏览器资料目录，并通过 `--remote-debugging-port=0` 在启动时强制开放随机调试端口。该方式能够隔离用户日常 Chrome，但 Google 登录会把“在已经受自动化控制的浏览器中首次登录”识别为不安全环境，即使用户亲自输入也可能被拒绝。

Chrome DevTools 与 Browser Harness 的原生实践是：用户先在普通浏览器状态完成登录，再到 `chrome://inspect/#remote-debugging` 主动允许远程调试，最后由 Agent 接管已登录会话。本迭代按该顺序修正 Alpha，同时保持唯一工具、专属资料目录和现有 Browser Harness 调用方式不变。

## 具体设计

### 1. Agent Runtime / Harness 层

- Alpha 继续用固定的专属 `user-data-dir` 启动独立可见浏览器，不扫描、不复用用户日常 Chrome 资料。
- 启动命令删除 `--remote-debugging-port=0`，保留禁止首次运行引导和默认浏览器检查的现有参数。
- 现有 `DevToolsActivePort` 读取、健康检查和显式 `BU_CDP_URL` 连接逻辑继续复用，不新增端口服务、CDP 客户端、MCP、数据库或进程扫描。
- Chrome 尚未产生健康端口时，不再将其统一视为浏览器故障；返回可恢复的 `status: user_action_required` 与 `action: enable_remote_debugging`。
- Chrome 启动命令正常退出且没有端口时，按“请求已转交给现有专属窗口或正在等待用户授权”处理，不误报资料目录锁；非零退出仍返回启动错误。
- 工具等待用户期间不持有共享浏览器锁。用户完成操作后，下一次普通工具调用重新读取端口并连接。

### 2. Tool / Skill / Plugin 能力层

- `browser_harness_exec` 的名称、参数、返回执行结果方式和默认注册保持不变，不增加 `manual_login` 模式或第二个浏览器工具。
- Skill明确区分：
  - `user_action_required` 是浏览器已打开并等待人工登录/原生授权，不是启动故障。
  - 用户先在可见的 Alpha 专属浏览器完成登录，再打开 `chrome://inspect/#remote-debugging`，允许远程调试并批准 Chrome 连接提示。
  - Google或其他身份提供方提示“不安全浏览器”时，不重复点击重试；用户临时关闭远程调试，完成登录后重新启用并回复“继续”。
  - 密码、MFA、验证码、授权同意、支付确认和不明确账号选择均交给用户处理，不在聊天中索取密码。

### 3. 登录态与持久化

- 人工登录与 Agent 接管始终共用 `state/browser-harness/browser-profile`，关闭或重新启用远程调试不会清理 Cookie、localStorage、IndexedDB 等浏览器资料。
- 登录态在同一资料目录、同一 Windows 用户下持续复用；网站主动使会话过期、用户退出、清理资料或更换系统用户时仍可能要求重新登录。
- 正式 EXE 打包时，浏览器资料必须作为用户持久数据放在稳定目录，不能随程序升级覆盖；该路径迁移留给正式打包迭代实现。

### 4. 用户流程

首次使用：

1. Alpha正常启动专属 Chrome，不开放命令行调试端口。
2. 用户在该窗口完成需要的账号登录。
3. 用户打开 `chrome://inspect/#remote-debugging`，允许此浏览器实例进行远程调试并批准连接。
4. 用户回到聊天回复“继续”；Agent再次调用原工具并接管。

登录过期或被阻止：

1. Agent停止重试并在聊天中给出明确步骤。
2. 用户临时关闭远程调试，在同一 Alpha 专属 Chrome 中完成登录。
3. 用户重新启用远程调试并批准连接，然后回复“继续”。
4. Agent重新读取当前页面和标签页，再从任务现场继续。

## 异常与边界

- 健康 `DevToolsActivePort` 已存在：直接连接，不重复启动 Chrome。
- 端口文件残留或内容无效：清理残留记录，正常启动专属 Chrome并等待原生授权。
- Chrome已经打开但尚未授权：启动请求正常转交后返回人工操作提示，不报告资料目录锁。
- Chrome非零退出、可执行文件缺失或端口文件无法清理：继续返回明确技术错误。
- 用户暂时不授权：任务保持未执行状态，不循环调用工具，也不长时间占用共享锁。

## 测试设计与验收标准

- 自动测试不启动真实浏览器。
- 验证启动参数中不存在任何 `--remote-debugging-port`。
- 验证健康原生端口仍可直接复用，失效端口仍会被清理。
- 验证等待超时返回可恢复的人工操作状态和 `chrome://inspect/#remote-debugging` 指引。
- 验证启动请求由现有 Chrome 正常接收并退出时不会误报故障，非零退出仍会报告错误。
- 验证 Skill包含人工登录、原生授权、不安全浏览器和恢复流程。
- 验证工具定义、工具注册、旧系统保留策略及其他后端测试不受影响。

## 本次明确不做

- 不增加工具、工具参数、数据库、MCP、前端按钮或浏览器设置页。
- 不自动输入密码、验证码或绕过 Google 登录限制。
- 不连接、复制或关闭用户日常 Chrome。
- 不在本次迭代迁移正式 EXE 的用户数据目录，也不实际打包 Chrome。
